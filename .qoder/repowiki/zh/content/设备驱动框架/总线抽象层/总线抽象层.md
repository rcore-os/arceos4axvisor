## 引言
本文档旨在深入解析 ArceOS 操作系统中总线抽象层的设计与实现，重点阐述 PCI 和 MMIO 两种总线接口的工作机制。文档将详细说明设备枚举、资源分配和地址映射的具体流程，并结合 axdriver 框架展示如何访问硬件设备。同时，分析静态绑定与动态探测的差异，并为开发者提供扩展新总线类型的指导。

## 项目结构
ArceOS 的总线抽象层主要位于 `modules/axdriver/src/bus` 目录下，包含对 MMIO 和 PCI 总线的支持。该模块通过条件编译特性（`bus-mmio` 和 `bus-pci`）控制不同总线类型的启用。配置信息由 `axconfig` 模块提供，包括设备内存范围和 ECAM 基地址等关键参数。

## 核心组件
总线抽象层的核心功能集中在 `AllDevices::probe_bus_devices` 方法中，该方法根据编译时启用的总线类型（MMIO 或 PCI）执行相应的设备探测逻辑。对于 MMIO 设备，系统遍历预定义的 VirtIO 内存区域进行探测；而对于 PCI 设备，则通过 ECAM 机制枚举总线上的所有设备并完成资源配置。

## 架构概述
ArceOS 的总线抽象层采用分层设计，上层为统一的设备容器 `AllDevices`，下层为具体的总线实现（MMIO/PCI）。系统启动时，`init_drivers` 函数调用 `probe` 方法，进而触发 `probe_bus_devices` 完成总线级设备发现。整个过程涉及物理地址到虚拟地址的映射、PCI 配置空间访问以及 BAR 资源分配等关键操作。

```mermaid
sequenceDiagram
participant 初始化 as init_drivers()
participant 探测 as AllDevices : : probe()
participant MMIO探测 as probe_bus_devices(MMIO)
participant PCI探测 as probe_bus_devices(PCI)
participant 驱动注册 as for_each_drivers!
初始化->>探测 : 调用
探测->>MMIO探测 : 条件编译分支
探测->>PCI探测 : 条件编译分支
MMIO探测->>驱动注册 : 遍历VirtIO-MMIO范围
PCI探测->>PCI探测 : 枚举总线(Bus 0~N)
PCI探测->>PCI探测 : 配置PCI设备(BAR分配)
PCI探测->>驱动注册 : 调用Driver : : probe_pci
驱动注册-->>PCI探测 : 返回设备实例
PCI探测-->>探测 : 注册设备
探测-->>初始化 : 返回AllDevices
```

## 详细组件分析

### MMIO 总线接口分析
MMIO（Memory-Mapped I/O）总线接口通过内存映射方式访问设备寄存器。在 ArceOS 中，该机制主要用于探测和初始化 VirtIO 设备。系统依据 `axconfig::devices::VIRTIO_MMIO_RANGES` 配置的内存范围，逐一尝试匹配已注册的驱动程序。

#### 实现流程
```mermaid
flowchart TD
Start([开始探测MMIO设备]) --> ForEachRange["遍历VIRTIO_MMIO_RANGES"]
ForEachRange --> ForEachDriver["遍历所有驱动"]
ForEachDriver --> ProbeCall["调用Driver::probe_mmio(addr, size)"]
ProbeCall --> DevFound{"设备被识别?"}
DevFound --> |是| AddDevice["添加设备到AllDevices"]
DevFound --> |否| NextDriver["下一个驱动"]
NextDriver --> ProbeCall
AddDevice --> EndLoop["结束当前range循环"]
EndLoop --> NextRange["下一个内存范围"]
NextRange --> ForEachDriver
AddDevice --> End([结束])
```

### PCI 总线接口分析
PCI（Peripheral Component Interconnect）总线接口采用 ECAM（Enhanced Configuration Access Mechanism）标准访问设备配置空间。ArceOS 通过 `PciRoot` 结构体管理 PCI 树状拓扑，实现设备枚举和资源配置。

#### 设备枚举与资源配置流程
```mermaid
flowchart TD
Start([开始PCI设备探测]) --> InitECAM["初始化ECAM基址<br/>phys_to_virt(PCI_ECAM_BASE)"]
InitECAM --> CreateRoot["创建PciRoot实例"]
CreateRoot --> ForBus["遍历总线 0 到 PCI_BUS_END"]
ForBus --> Enumerate["enumerate_bus(bus)"]
Enumerate --> ForDevice["遍历每个BDF设备"]
ForDevice --> IsStandard{"HeaderType == Standard?"}
IsStandard --> |否| Skip["跳过非标准设备"]
IsStandard --> |是| ConfigDevice["调用config_pci_device()"]
ConfigDevice --> ForBar["遍历BAR 0-5"]
ForBar --> BarInfo["获取BAR信息"]
BarInfo --> NeedAlloc{"Address==0 && Size>0?"}
NeedAlloc --> |是| AllocAddr["从PCI_RANGES分配新地址"]
NeedAlloc --> |否| ReadAgain["重新读取BAR信息"]
AllocAddr --> SetBar["调用set_bar_32/set_bar_64"]
SetBar --> ReadAgain
ReadAgain --> LogBar["记录BAR映射信息"]
LogBar --> NextBar["下一个BAR"]
NextBar --> ForBar
ForBar --> EnableDev["启用设备: IO+MEM+BUS_MASTER"]
EnableDev --> ProbeDriver["调用Driver::probe_pci()"]
ProbeDriver --> DriverMatch{"驱动匹配成功?"}
DriverMatch --> |是| AddDevice["添加设备到AllDevices"]
DriverMatch --> |否| Continue["继续下一个设备"]
AddDevice --> End
Continue --> End
```

### 动态驱动框架分析
当启用 `dyn` 特性时，ArceOS 使用基于 FDT（Flattened Device Tree）的动态驱动加载机制。此模式下，`setup` 函数接收设备树地址作为参数，通过 `rdrive` 库解析设备节点并自动匹配驱动。

#### 动态PCI控制器驱动工作流程
```mermaid
sequenceDiagram
participant Setup as setup(dtb)
participant RDrive as rdrive : : init(Fdt{addr})
participant Register as register_append(driver_registers)
participant Probe as module_driver!(probe)
participant IoMap as iomap(addr, size)
participant PlatDev as PlatformDevice : : register_pcie
Setup->>RDrive : 初始化FDT平台
RDrive->>Register : 注册静态驱动表
Register->>Probe : 触发兼容性匹配
Probe->>Probe : 匹配"pci-host-ecam-generic"
Probe->>IoMap : 映射PCIe寄存器区域
IoMap-->>Probe : 返回虚拟地址
Probe->>Probe : 解析node.ranges()
Probe->>Probe : 设置mem32/mem64资源池
Probe->>PlatDev : 注册PCIE驱动实例
PlatDev-->>Probe : 完成注册
Probe-->>Register : 返回成功
```

## 性能考虑
静态编译时绑定避免了动态调度开销，适合单一设备场景；而运行时动态探测虽然引入少量间接调用成本，但支持多实例和热插拔，灵活性更高。PCI 总线的 ECAM 访问具有固定延迟，而 MMIO 探测效率取决于内存范围数量和驱动匹配速度。

## 故障排除指南
常见问题包括设备未被识别、BAR 分配失败或 I/O 映射错误。应首先检查 `axconfig` 中的地址范围配置是否正确，其次确认设备树中相关节点是否存在且兼容性字符串匹配。调试日志可通过启用 `log` 特性获取详细探测过程。
